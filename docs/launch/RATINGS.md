# Ratings launch decision

Recommendation, awaiting owner acceptance: launch without persistent community voting. Keep the approved seven-ball visual and honest unrated aggregates. If retaining interactive preview controls, merge [PR #29](https://github.com/siruiusamory-cmyk/legacy-of-goku-hub/pull/29) first: its heading explicitly says “Preview only · not saved”. No success message, saved vote, fabricated average or count is permitted. The preview is not community voting. Removing/disabling selection altogether would require a separate small reviewed change, not a redesign.

Research checked November 15, 2026. These are design options, not installed services or promised free production capacity.

| Option | Identity, abuse and privacy | Static compatibility, cost and operations | Assessment |
| --- | --- | --- | --- |
| No persistent votes | No voter identity, tracking, duplicate-vote or deletion obligations; no average until real votes exist | Existing static build, no new service or cost | Recommended for launch; directory and submissions work independently |
| GitHub-hosted vote ledger (issues/discussions) | Authenticated numeric user IDs; select the latest valid vote per user/project. Public choices expose identity and voting history. Multiple accounts remain possible; moderation and eligibility rules needed | A scheduled trusted reader can export aggregates for static builds; GitHub availability/API limits and delayed updates apply. Existing UI cannot claim success without an authenticated write flow | Low infrastructure, substantial product and moderation work; reactions do not naturally encode a single 1–7 score |
| GitHub sign-in + Cloudflare Worker/D1 | Server verifies identity; unique `(project_id, provider_user_id)` with transactional upsert. OAuth state/PKCE where supported, secure sessions, CSRF/origin checks, bounded input, rate limits and account-abuse review required. Store minimal IDs and scores; publish aggregates only | Static frontend calls a separate HTTPS API. D1 Free currently includes 5M rows read/day, 100K written/day and 5 GB storage; Workers has separate quotas. Free-limit exhaustion fails requests. Own auth/session code, backups, exports and incident response | Viable future lean backend if owner accepts an additional service and maintenance; not part of this milestone |
| Supabase Auth/Postgres | GitHub sign-in, server-enforced ownership/RLS and a unique voter/project constraint. Never expose service-role keys; isolate raw votes from public aggregate views. Same multi-account limitation and privacy/deletion work | Static client can call hosted APIs. Free currently includes 50K monthly active users and 500 MB database, but pauses after a week of inactivity; Pro starts at $25/month. Requires policy testing, backups and quota monitoring | Convenient managed auth, but free inactivity behavior and paid reliability conflict with current launch simplicity/no-paid-service preference |

One authenticated account is not one human. Cookies, localStorage, IP limits or CAPTCHA alone cannot enforce one user vote. GitHub reactions allow several reaction types and do not supply seven mutually exclusive numeric scores. Never put OAuth client secrets, privileged database credentials or a maintainer GitHub token into static JavaScript. GitHub's web authorization flow requires a secret for ordinary code exchange, so this cannot simply be added to Pages-only client code.

For a future backend: accept integers 1–7 only for eligible stable project IDs; one current score per authenticated numeric user ID/project, edit replaces prior score. Compute `count = number of eligible current rows`, `average = sum(score) / count`, round only the display to one decimal; zero rows means null average and “Not rated yet”. Define exclusions and appeal procedures for abusive accounts, deletion/export retention, moderation audit records and aggregate freshness. Distinguish an unavailable service from zero votes; show last-verified aggregates with a timestamp or unavailable status, never manufacture zero votes. Test concurrent duplicate updates, unauthorized writes and aggregation before enabling.

The recommendation is based on the operational burden above, not an inference that any provider guarantees abuse prevention or permanent free availability. No ratings schema, backend, account, OAuth app or dependency was created.
